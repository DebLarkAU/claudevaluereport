Pulling data from the TrendAI Vision One portal (`portal.xdr.trendmicro.com`) via Blueprint MCP. Each module loads inside **nested same-origin iframes** (e.g. `#__CAS_APP_CONTAINER` → `ui/cas/dashboard`, `#__ASD_CONTAINER`, `#__SJG_CONTAINER`). Used for [[project-jhc-value-report-deck]].

- **Attach** to the existing portal tab (it's usually already open, was tab 9). After navigating via menu/link the tab handle goes null — re-`browser_tabs attach index=9`.
- **Read/click via DOM walk, not coordinates.** `browser_interact` trusted mouse_clicks only reach the OUTER iframe (`found iframe#__X_CONTAINER`) and do NOT propagate to nested iframes — so coordinate clicks on nested content silently fail. Instead use `browser_evaluate` with an `allDocs()` helper that BFS-walks `document` + every `iframe.contentDocument`, find the element by text, and call `.click()`. This works for tabs, menu items, table sorting.
- **Left-nav navigation:** the side menu lives in the TOP document. Click `#menu<id> .ant-menu-submenu-title` (e.g. `#menudashboard` = Cyber Risk Exposure Management, `#menuidentitysecurity`, `#menuemail_security_operations`), then `.click()` the submenu `<li>`/text by exact match.
- **Custom dropdowns / time-range selectors** (Tonic UI `data-tonic="Menu"`): open by `.click()` on the `<button>` whose text matches "Last 24 hours". Then to change selection, `.click()` the **`<label>`** containing "Last 30 days" (clicking the inner radio input does NOT update React state and reverts; the label works), then `.click()` the **Apply** button. Each widget has its OWN time selector — Threat Detection's "Overall Threat Detections" and Risky User Detection's "Top Users with Targeted Attack Risks" are separate; set each. Wait ~4s after Apply (data reloads, briefly shows 0 / "No data").
- **Tables:** rows are virtualized; extract via DOM (`[role=row]`/`[role=cell]`) inside the right grid. Truncated cells (ellipsis) still hold full text in DOM / a `title` attr; regex `[\w.\-]+@[\w.\-]+` to recover full emails.
- **Downloads are BLOCKED in this automated browser** (CDP-initiated downloads never hit `~/Downloads`; the download popover won't open for synthetic OR trusted clicks). For report PDFs (Reports module), have the USER click the download icon themselves, then read the PDF from `~/Downloads`. PDF text via `pypdf` (poppler not installed, so Read-tool image rendering of PDFs fails — use pypdf `extract_text`).
- Reports → Generated reports → "Reports Created from Templates": System-Generated MDR report is template "Managed Detection and Response", Created by "System Generated", monthly.
- **Direct API counting (best for aggregates):** instead of scrolling virtualized grids, call the module's search API with **synchronous XHR** from a `browser_evaluate` (async/fetch results don't return). Endpoint Event Viewer = `POST /public/aew/v1/security-events/<slug>/search` (slugs: anti-malware, web-reputation, intrusion-prevention, application-control, device-control, firewall). Auth header is **`uic-token`** (value from `localStorage['uic-token']`, NOT Authorization/Bearer — cookies/Bearer give 401). Request body: `{searchCriteria:[],period:{start,end}/*epoch sec*/,eventType:["all"],groups:[],customTags:[],searchTimePerBatch:20,eventCountPerBatch:500,maxEventCount:1000,nextToken:"",nextLink:""}`. Response `{events:[...],nextToken}`; paginate by feeding `nextToken`/`nextLink` back until null. Action field is **`actionTaken`** (array) for anti-malware/web-reputation/device-control, but **`action`** (array) for intrusion-prevention/firewall. `Date.now()` works fine inside browser_evaluate (only blocked in Workflow scripts). Token also lives in `localStorage['ember_simple_auth:session'].authenticated.token` (different, ~260 chars) — not needed for AEW.
- **Endpoint Inventory (VES) won't render in the automated browser** (spinner hangs; the page never fires its own `bigtable-endpoints/search`). Get deployment counts via the API instead: `POST /public/ves/v1/bigtable-endpoints/search` with body `{encoded_filter: btoa(JSON.stringify({})), limit:500, offset:N}` (both `encoded_filter` AND `limit` are required or it 400s; `uic-token` header). Response `{endpoints:[...], total}`. Filter keys are unknown (passing `{managed:true}` is ignored → returns all), so page all rows (limit 500, 4 pages for ~2k) and **tally client-side inside browser_evaluate, returning only the counts**: managed split = `managed` bool (true→All managed, false→Unmanaged); "Standard Endpoint Protection" = `integrated_endpoint_sensor_status==='disabled'`, "Sensor only" = `==='unknown'`; "Deployment failed" = `xes_deployment_status==='fail_install'`.
- **AEW request limits (learned 2026-06-22):** `eventCountPerBatch` max is **500** (sending 5000 → HTTP 400 `Invalid request format`). For high-volume slugs (Intrusion Prevention ~14k/30d) chunk the period into ~5-day windows AND run **≤2 windows per `browser_evaluate`** — 6 windows with pagination in one call times out the CDP connection (`forwardCDPCommand` timeout; recover via `disable`→`enable`→re-attach, and note **tab indices shift on reconnect** / when the user opens tabs, so re-`list` and find the portal tab by URL each time). Each 5-day IPS window ≈ 1300–4100 events / 3–9 pages. Sum action tallies client-side. IPS action field is `action`; AM/WR/DC use `actionTaken`.
- **VES endpoint counts (corrected 2026-06-22):** "EDR sensor active / recording" = `xes_deployment_status==='recording'` (NOT an `integrated_endpoint_sensor_status` mapping — that field is only disabled/unknown and does NOT track EDR). "Deployment failed" = `fail_install` + `fail_precheck`. `managed`(bool) splits managed/unmanaged. For the Standard-EPP vs Sensor-only split, DON'T derive it from the bigtable fields — `integrated_endpoint_sensor_status` disabled/unknown badly over-counts "sensor only" (gave 138 vs the true 12). **The authoritative source is the Endpoint Inventory page** (`#/app/ves-inventory`) left rail "SECURITY DEPLOYMENT" facet: All managed endpoints / Standard Endpoint Protection / Sensor only (and "Deployment failed" + "Unmanaged endpoints" + "Sensor disabled" facets). The page DID render on 2026-06-22 (earlier note said it hangs — it loads now; the facet counts are visible even though the grid is virtualized). June 2026 Intralot: All managed 657 = Standard EPP 645 + Sensor only 12; Unmanaged 126; Deployment failed 9; Sensor disabled 18.
- **BEST WAY to get restructured-CREM Cyber Risk numbers (learned 2026-06-22): read the dashboard's own JSON APIs via `browser_network_requests`, don't DOM-scrape.** The Risk Overview is the new "sase" SPA; its data loads from `/public/ass/api/v1/...` XHRs. Flow: attach → `browser_network_requests clear` → `browser_navigate reload` → wait ~6s → `browser_network_requests list urlPattern='/public/' limit=100` → `action='details' requestId='<id>'` on the ones you need (responses are clean JSON, no auth juggling). The slide-2 endpoints:
  - **Devices:** `GET /public/ass/api/v1/trilogy/riskOverview/visibilityAttackSurface?type=device` → `{total, full, partial, limited}`. Map **discovered = total**, **assessable = managed = full** (partial+limited = the not-fully-visible gap). (`riskOverview/estimateAttackSurface?type=device` also gives `discoverable`.)
  - **Accounts:** `GET /public/ass/api/v1/trilogy/riskOverview/userAccounts/riskLevelBar` → `{domainAccounts:{total,low,medium,high}, serviceAccounts:{...}}`.
  - **Vulnerabilities/CVEs:** `GET /public/ass/api/v1/risks/factorStatistics?period=30&scoringAlgorithm=v2` → array of factors; find `factorName:"Vulnerability detection"` where **`count`=High, `mediumCount`=Medium, `lowCount`=Low** (sum = total CVEs). Other factors (Account compromise, System/Security configuration, Threat detection, etc.) carry their own counts here too.
  - **Connected products (for "what vendors/integrations"):** `GET /public/ass/api/v1/customer/devices` → list of `deviceProductId` actually connected (e.g. `aad`=Entra ID, `xes`, `sao`, `sca`, `xca`, `sig`, `xms`, `dsr`, `tlc`, `aal`, `dlt`). NOTE: `risks/riskFactorList` lists every *supported* sensor (vds-okta, vds-qualys, vds-rapid7, vds-tanium, vds-sentinel-one, …) — that's the CATALOG, not Intralot's actual stack; don't confuse the two.
  - **MTTP / Average Unpatched Time gauges** are Highcharts; the decimal value is readable by scanning iframe `<text>`/`tspan` for a `\d+\.\d` (got Average Unpatched Time = 35.6 this way). The MTTP headline gauge value resisted both SVG-text and screenshot (iframe won't scroll: window not scrollable, no overflow container, doc scrollingElement scrollTop stuck at 0, getBoundingClientRect returns 0/iframe-origin) — may need the dedicated Vulnerabilities page. June 2026 Intralot slide-2 actuals: discovered 695 / assessable+managed 666; domain 4,190 / service 920; 855 CVEs (61H/676M/118L); avg unpatched 35.6 d.
- **CREM was restructured (~2025-04, portal shows a "Cyber Risk Exposure Management is restructured" banner):** the old Attack Surface Discovery / Operations menu items are gone, and the device discovery split (discovered/assessable/managed), CVE H/M/L, MTTP, and domain/service account counts now live in below-the-fold detail iframes/Highcharts canvases on the Cyber Risk Overview that **don't surface text to DOM scraping** and resist scrolling. The CRI number and category risk levels (Devices/Internet-Facing/Accounts/Applications/Cloud Assets) ARE readable on the overview; the sub-metrics need drilling into each category's detail page. Regional-avg comparison line (toggle "Compare with other orgs") also won't yield a clean per-series value via tooltip/DOM. Budget extra time or expect to carry these forward.
- **Credits:** Platform Usage and Credits page (menu TrendAI Flex Licensing → Platform Usage and Credits; loads iframe `ui/bc/company/static/credit/index.html`). Headline tiles (Balance, % remaining, Planned usage, Estimated drawdown, Expiring soon) read cleanly via **screenshot**; the iframe doesn't scroll for the month-by-month table and DOM-scrape of the tiles returns blank. Direct hash-URL nav redirects to `#/dashboard` — navigate via the menu DOM-walk instead.
- **react-select dropdowns (class `customized-select__*`, e.g. Intelligence Reports "View: Matched sweeps only" filter) don't open on `.click()`** — focus the inner `input` and dispatch a `keydown` ArrowDown (`new KeyboardEvent('keydown',{key:'ArrowDown',keyCode:40,which:40,bubbles:true})`), then read/click `.customized-select__option` by text and fire pointerdown+mousedown+mouseup+click on it. (Distinct from Tonic UI `data-tonic=Menu` selectors which DO open on `.click()`.)
